# Reconocimiento por sesión: texto editable integrado

El contrato vigente de `../gpc_back/docs/certificate-origins-api-contract.md` admite mensaje y motivo personalizados. Este documento reemplaza la descripción anterior que los consideraba pendientes de Laravel.

El asistente por sesión tiene cuatro pasos: Información, Texto del reconocimiento, Previsualización y confirmación, y Enviar a Gerencia. El paso 2 usa controles reactivos y el validador de texto plano de Capacitación: mensaje obligatorio de hasta 1200 caracteres Unicode y motivo obligatorio de hasta 500. Rechaza HTML y controles peligrosos. Los textos se conservan al retroceder.

Previsualizar PDF solicita `revisar_documento` en `/api/certificaciones/ponente_sesion/{id_actividad_ponente}/preparar`, con modalidad sesión, ID real y ambos textos. Se comprueban identidad, textos devueltos y SHA-256 del PDF del servidor. El visor existente debe notificar que visualizó ese archivo antes de confirmar su preparación en la misma pantalla. Angular no genera el PDF. Por solicitud de interfaz, no se repiten motivo, mensaje ni la leyenda de borrador debajo del PDF.

Editar cualquiera de los textos elimina revisión, token y vista previa. Una respuesta pendiente se descarta si cambió el contenido. La caducidad del token actualiza la pantalla y bloquea confirmar; se puede volver al paso 2 y generar otra revisión conservando los textos. Solo una confirmación exitosa permite avanzar al paso 4; no inicia el envío a Gerencia.

Confirmar preparación es una acción explícita con token y textos exactos de la revisión. Las operaciones en curso bloquean solicitudes simultáneas. Recuperar una preparación conserva mensaje aprobado, motivo, hash y documento original, deshabilita los controles y no permite prepararla otra vez. El envío a Gerencia mantiene su revisión y confirmación explícitas independientes.

Las pruebas de Angular usan respuestas HTTP y documentos de prueba; no constituyen una prueba de composición del PDF institucional contra Laravel en ejecución. Para comprobar visualmente el resultado real se requiere recorrer el asistente autenticado con una asignación elegible. No se modifican backend, base de datos, Portal Público ni PDFs existentes.

Separación final de preparación y remisión: el paso 3 confirma únicamente la preparación y conserva el ID documental de Laravel; la recuperación rechaza un ID diferente. El paso 4 muestra Preparado para enviar a Gerencia cuando el estado real es PREPARADO, incluso si una etiqueta del servidor contradice ese estado. Ver certificado abre el PDF guardado sin remitirlo. Solo el clic Enviar a Gerencia obtiene revisión de envío y confirma la remisión con ese ID documental. Los fallos conservan el documento preparado y permiten reintentar. Un documento ya remitido se recupera por ID sin repetir el POST, y el éxito solo se comunica ante PENDIENTE_FIRMA confirmado por la API.
